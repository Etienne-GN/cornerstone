# Omnibar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fork of dash-to-panel that mirrors primary-bar indicators onto
every monitor's bar and adds a single Action Center popup (quick settings,
media + notifications, calendar) opened from any bar.

**Architecture:** Fork upstream dash-to-panel git history into
`~/git/omnibar`. Indicator mirroring is ported from Multi Monitor Bar (MMB)
into `src/mirror/` and driven by a new controller hooked on dash-to-panel's
`panels-created` event. The Action Center lives in `src/actionCenter/` and
moves GNOME's own widgets (quick settings grid, `CalendarMessageList`,
calendar column) into one popup, restoring them exactly on disable.

**Tech Stack:** GJS (ESM), GNOME Shell 50/51 extension API, St/Clutter,
Adw/Gtk4 prefs, GNU make, `node --test` for unit tests, nested
`gnome-shell --devkit --headless` for integration tests.

**Spec:** `docs/superpowers/specs/2026-10-21-omnibar-design.md` (copied into
the repo by Task 1 from `~/claude/specs/`).

## Global Constraints

- Supported shells: GNOME 50 and 51 only; `shell-version: ["50", "51"]`.
- UUID `omnibar@etienne-gn.github.io`; schema id
  `org.gnome.shell.extensions.omnibar`; schema path
  `/org/gnome/shell/extensions/omnibar/`; display name `Omnibar`;
  gettext domain `omnibar`. The name is temporary: `metadata.json` is the
  single source for identity, everything else derives from it or is
  rewritten by `tools/rename.sh`.
- License GPL-2.0-or-later; keep upstream headers; files adapted from MMB
  carry a header crediting Frederyk Abryan's Multi Monitor Bar and spin83's
  Multi Monitors Add-On.
- `global.dashToPanel` stays (same object, same `panels` member and
  `panels-created` signal) for date-menu-formatter compatibility.
- Never test in the live session. Integration tests run only through
  `tests/nested/run.sh` (isolated XDG dirs, own D-Bus session, headless).
  Never run `make install` against `~/.local/share`; never call
  `gnome-extensions enable/disable` outside the nested harness.
- Heavy commands (nested shell, lint, tests) run under `nice -n 19`.
- No files in `/tmp`; scratch lives in `~/git/omnibar/.nested/`
  (gitignored). Set `TMPDIR` there for the harness.
- Errors are logged with `console.error('[omnibar] <context>', e)`, never
  swallowed. Prefer feature detection over `Config.PACKAGE_VERSION`
  compares for 50/51 differences.
- Follow upstream style: prettier (`semi: false`, single quotes, 2-space),
  ESM imports, `GObject.registerClass` for actors, `_dtp`-style private
  prefix becomes `_omni` for new properties put on GNOME objects.
- Commits: one concern each, lines ≤ 80 chars, no emoji, only trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No remote is
  added except `upstream`; nothing is pushed.

## Review Focus

1. **Screen lock / unlock.** The extension has no `session-modes`, so GNOME
   disables it on lock and re-enables it on unlock. Every lock is a full
   disable/enable cycle: mirrors, moved widgets and patches must restore and
   re-apply cleanly every time (Task 2 smoke runs 5 cycles; Task 6 and
   Task 9 scenarios cycle with mirrors/Action Center active).
2. **Monitor hotplug / dash-to-panel `_reset`** (monitors-changed, primary
   monitor or panel-position change) while mirrors exist or the Action
   Center is open: no crash, mirrors rebuilt on the new panels, Action
   Center closes and keeps its widgets (Task 6, Task 10 scenarios).
3. **Indicator extension churn**: an indicator added, removed or recreated
   at runtime (appindicator restarting, extension reload) — the mirror
   follows within one debounce, no "already disposed" warnings (Task 6).
4. **Disable while a popup is open**: disabling with the Action Center open,
   or with a quick-settings submenu open, restores every widget to its
   original parent and index and leaves no modal grab (Task 9).
5. **Vertical bars** (panel on left/right): mirrors use the vertical remap
   and the Action Center anchors beside the bar, not off-screen (Task 6,
   Task 10).

### Task 9: Action Center popup and content moving

**Files:**
- Create: `src/actionCenter/widgetMover.js`,
  `src/actionCenter/actionCenter.js`, `tests/unit/widgetMover.test.mjs`,
  `tests/nested/scenarios/actionCenter.js`

**Interfaces:**
- `widgetMover.js`: `class WidgetMover { move(actor, newParent, index = -1);
  restoreAll(); }`. `move` records original parent and the next sibling
  (fallback index) and is idempotent per actor; `restoreAll` restores in
  reverse order and reinserts before the recorded sibling if still a child
  of the original parent, else at the recorded index, else appended.
- `actionCenter.js`: `class ActionCenter` with `enable()`, `disable()`,
  `open(sourceActor)`, `close({animate})`, `toggle(sourceActor)`,
  `isOpen`, signal-free; internally a `PopupMenu.PopupMenu` subclass
  (`ActionCenterMenu`) whose `box` holds a vertical `St.BoxLayout`
  `omni-action-center` with three hosts in order: `qsHost`, `messagesHost`,
  `calendarHost`; menu added to `Main.uiGroup`, own `PopupMenuManager`.
- Content moved on `enable()`. No wait for the async
  `QuickSettings._setupIndicators` is needed: items are inserted into
  `_grid`/`_overlay` wherever those actors live, so late items land in the
  Action Center too (assert this in the Step 4 scenario by adding an
